# 工程与数据边界

采集器获取公开市场、财务、公告、新闻和研报；原始 SQLite / 文件队列承担断点与缓存。增量导入把标准化记录写入 PostgreSQL，正文恢复、OCR、全文与向量任务使用版本化队列。派生图谱、因子与预测记录同样入 SQL，并通过统一数据目录说明口径、可用时间和依赖。

Agent 工具与日报读取这些 SQL 契约，保留时间截点、证券身份和证据来源。多步 Agent 的计划、工具选择、完成检查与结果呈现位于 `packages/mmclaw/mmclaw`。预测试验和模型发布门槛属于业务逻辑，目录整理不会改变批准状态。

模型网关位于独立服务目录，负责并发租约、冷启动等待和空闲关闭。模型依赖与 GPU 部署按环境配置，日常纯业务测试只使用模拟后端。

多机部署通过 SSH 回环隧道接入认证节点，按 GPU 容量选择模型落点；节点自己持有请求租约并负责空闲回收，数据库与业务队列不迁移。配置、验收和回滚见 [远端 GPU 推理](REMOTE_GPU_INFERENCE.md)。

## 可逐步演进的入口

- `apps/finagent` 保留现有脚本相对路径，以避免一次性重写采集、SQL 和报告约数百个调用点。
- `MMClaw`、`runtime`、`systemd`、`sql`、`docker/postgres` 是指向本仓库组件目录的兼容链接；它们不指向生产目录。
- `src/xtrastock` 是共享基础设施的唯一实现。新增数据库、API 配置从这里进入，禁止复制连接参数。
- `database/postgres` 保存既有 SQL 基线和历史迁移，`database/migrations` 保存后续数据契约增量。结构化迁移需逐步建立版本记录，不能以文件名字典序替代依赖排序。
- `config/repository_components.json`（位于业务 app 内）登记当前维护入口，`make doctor` 检查路径、语法、数据契约依赖和部署模板。

## 开发与运行分离

Git 只携带代码、示例、可公开的合成测试和维护文档。数据库卷、实际 API 地址、密钥、群标识、聊天历史和业务研究文件不包含在仓库中。首次发布使用干净历史，不继承旧生产仓库的提交和未审核历史文件。

当前整理不停止、不重启、不自动切换既有服务。将生产实例迁移到此目录需要单独填写配置、验证数据库版本和所需数据，再按部署说明执行。
